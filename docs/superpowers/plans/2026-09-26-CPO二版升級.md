## 意外發現／踩雷
- 手機樣式用到的 class：`.pts`＋`.pnt`（一句一行編號，`data-n` 是編號、`.lead` 不編號）、`.pts2`＋`.pnt.co`（FAU 說明框，一家一列）、`.kv`（兩欄表固定欄寬）、`.m-hide`（手機上隱藏）、`#ychain`／`#readmap`（步驟框左欄寬度）。這些在電腦上都沒有樣式。
- 把句子包進 inline span 後，電腦版版面不變，但少數幾個字的邊緣抗鋸齒會有肉眼看不出的差異（文字被拆成不同的排版區段，次像素位置差不到 1/64px）。
- Git Bash 會把以 `/` 開頭的指令參數轉成 Windows 路徑（`/.tmp-rv/x.html` 變成 `C:/Program Files/Git/.tmp-rv/x.html`）；傳網址路徑時不要以 `/` 開頭，或加 `MSYS_NO_PATHCONV=1`。這次害基準截圖整批空白。
- 摺疊（`details.fold`）裡的圖如果也帶 `.rv`，它在收合時永遠不會進入畫面、觀察器不觸發，打開後就一直是透明的。摺疊裡的東西不要加 `.rv`；另外已加「載入 2 秒後全部顯示」的保險。
- 內建瀏覽器窗格被藏起來時，頁面是 hidden 狀態：動畫停在第一格、觀察器不觸發，量到的透明度都是 0，不能拿來判斷有沒有顯示。視覺驗證用無頭 Chrome 截圖。
- 無頭 Chrome 一次跑 40 幾張截圖約 4 分鐘，要把指令的逾時設到 10 分鐘。
- CPO.html 是 CRLF 換行：用 Python 整檔重寫時要 `open(..., newline="\r\n")`，否則整檔變 LF。
- 無頭 Chrome 截圖時 `.rv` 淡入動畫可能還沒跑完（頁面有 1.45MB 圖片、載入慢），截圖工具要注入 `.rv{transition:none!important}`。
- 內建瀏覽器會快取舊版 CPO.html，改完要加 `?v=…` 之類的參數重新載入再驗證。
- 第 07 章 `.ins .rw b{display:block}` 會把內文所有粗體都當成小標題各佔一行，已改成只套用每列第一個粗體（`.ins .rw>b:first-child`）。
- 在 bash 雙引號裡用 `python -c` 寫含反引號的文字，反引號裡的內容會被 shell 當指令吃掉；含反引號的修改改用編輯工具。
- 另一個 session（排程入庫模式）與本 session 同時把四份報告寫進同一張主題卡 → 重複列；已在 `D:\投資日報\CLAUDE.md` 入庫流程第 4 步加「動手前重新 Read 整張卡」。
- 使用者用 @ 指到 Downloads 的四份 PDF，實際檔案在 `D:\投資日報\收件匣`；找不到檔先看收件匣。
- 手機寬度截圖：headless Chrome 視窗最小約 500px，要用 375px 寬 iframe 包住頁面再拍（記憶 feedback-visual-verify-in-browser 第 6 條）。
